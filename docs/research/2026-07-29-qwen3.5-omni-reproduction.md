# Qwen3.5-Omni 技术报告对比与可复现方案

日期：2026-07-29
本地基线：`391d0186cb225f41f8e47aa600c36da0bc6b21e4`
目标定义：论文级开放功能原型，不宣称复现专有 Plus/Flash checkpoint

实现状态更新（2026-07-30）：项目已补齐 legacy 全注意力 Thinker 的 typed
prefill/decode KV 状态、媒体仅 prefill 一次、会话所有权隔离和 decode benchmark；
同时已有独立的实验性媒体序列与 TM-RoPE 契约。它们是复现路线的基础设施，
不是 Qwen3.5 GDN、256K context、ARIA、Talker 或 codec 的实现，也没有改变
Qwen3.5-Omni 无公开权重、无法做 checkpoint 级复现的边界。

## 1. 核验结论

Qwen3.5-Omni 是真实发布的 Qwen 模型系列：

- [API 于 2026-03-30 发布](https://www.alibabacloud.com/help/en/model-studio/newly-released-models)；
- [技术报告 arXiv v2](https://arxiv.org/html/2604.15804v2)发布于
  2026-04-21；
- 官方服务包含 Plus、Flash 和 realtime 变体；
- 报告说明模型支持文本、图像、音频和视频理解，以及实时文本/语音输出。

但是，截至 2026-07-29，Qwen3.5-Omni 没有开放：

- 模型权重；
- Plus/Flash 的精确配置；
- Qwen3.5-Omni 本地推理实现；
- 音频 tokenizer/codec 权重；
- 训练代码和完整训练 recipe；
- 模型权重许可证。

报告本身明确写的是通过 API 公开访问。官方 Hugging Face 没有
`Qwen3.5-Omni` 模型仓库，QwenLM GitHub 也没有对应源码仓库。Transformers
稳定版提供 `qwen3_5`、`qwen3_5_moe` 和前代 `qwen3_omni_moe`，但没有
`qwen3_5_omni`。

所以可复现目标必须拆成三层：

1. **精确可验证**：前代 Qwen3-Omni 的开放 Omni 管线。
2. **精确可验证**：公开 Qwen3.5 骨干的 Hybrid Attention/MoE/GDN。
3. **论文级重建**：将前两类开放组件与论文披露的 AuT、TM-RoPE、ARIA 和
   训练阶段组合成 `Qwen3.5-Omni-inspired` 原型。

第三层不能被命名为官方 Plus/Flash 复现，也不能声称 checkpoint 兼容。

## 3. Qwen3.5-Omni 报告披露的架构

### 3.1 总体结构

```text
文本 / 图像 / 音频 / 视频
            │
     Vision Encoder + AuT
            │
  Hybrid-MoE Thinker
            │
       文本与工具调用
            │ 高层多模态状态、历史文本、当前流式文本
            ▼
 Hybrid-MoE Talker + ARIA
            │ 主 RVQ codebook
            ▼
  Dense Transformer MTP
            │ 其余 codebooks
            ▼
     causal Code2Wav
            │
            ▼
       逐帧流式波形
```

**论文明确：**

- Thinker 和 Talker 均采用 Qwen3.5 风格 Hybrid Attention + MoE；
- Hybrid backbone 混合 Gated Delta Net 和 full attention；
- AuT、Thinker、Talker、MTP、Code2Wav 支持流式路径；
- Vision Encoder 为 SigLIP2 系列，论文表格将其标为非流式；
- 模型总规模只描述为“hundreds of billions”，没有 Plus/Flash 的精确宽度、
  层数、专家数或激活参数。

不能把 Qwen3.5-Omni-Plus 直接等同于公开的 Qwen3.5-397B-A17B，也不能把
Qwen3.5-35B-A3B 的精确配置冒充 Flash 配置。

### 3.2 Tokenizer

**论文明确：**

- 使用 Qwen3.5 byte-level BPE；
- 词表由前代约 150K 扩大到约 250K；
- 多数语言 token 编解码效率提升约 10%–60%。

**公开骨干参考：**

- Qwen3.5-35B-A3B 的精确 `vocab_size` 为 248,320；
- 最大上下文配置为 262,144。

248,320 是公开骨干的精确值，可以作为实现参考，但报告没有承诺所有 Omni
Plus/Flash checkpoint 使用完全相同的 embedding schema 和媒体特殊 token。

### 3.3 AuT 音频编码器

**论文明确：**

- 输入 16 kHz；
- 128-channel Mel；
- 25 ms window、10 ms hop；
- 四个 Conv2D block，总下采样 16 倍；
- 输出 6.25 Hz，每个 audio token 约对应 160 ms；
- 使用约 4,000 万小时 audio-text 数据训练；
- 中文、英文、其他语言的比例约为 `3.5:3.5:3`；
- 使用动态 attention window 兼顾实时 cache 和离线理解。

与前代 Qwen3-Omni 相比，音频 token rate 从约 12.5 Hz 降到 6.25 Hz，能够
降低长音频序列长度，但要求新的时间网格、cache 和训练分布。

### 3.4 视觉、视频、融合和时间

**论文明确：**

- 使用 Qwen3.5 vision encoder 处理图像和视频；
- 图片和视频保留 patch sequence；
- 视频使用动态 FPS；
- 音频和视频按时间交错；
- 使用 TM-RoPE；
- 每 160 ms 音频对应一个 temporal ID；
- 视频帧按真实 timestamp 映射到相同的 160 ms 时间分辨率；
- 每个视频/音视频 temporal patch 前加入格式化秒数 timestamp；
- 纯音频序列随机插入 timestamp；
- 不同模态的位置连续衔接。

显式 timestamp 是对前代绝对 temporal position 稀疏问题的修正。它不是
TM-RoPE 的替代，而是与 TM-RoPE 一起使用。

### 3.5 Hybrid Attention 与 Gated Delta Net

**论文明确：**

- Thinker 和 Talker 使用 Hybrid-MoE；
- GDN 用于降低长音视频序列中的 KV-cache I/O；
- chunked prefill 与 Hybrid backbone 共同提高并发和首包速度。

**公开骨干参考：**

公开 Qwen3.5-35B-A3B 使用三个 linear-attention layer 后接一个
full-attention layer的 3:1 pattern，并包含：

- Q/K/V projection；
- beta、decay 和 z gate；
- depthwise causal convolution；
- key×value recurrent matrix state；
- 固定尺寸的 recurrent cache；
- full attention 的 Q/K norm 和 output gate；
- SwiGLU routed/shared experts；
- 256 routed experts、top-8。

这些机制可作为 Qwen3.5-inspired Thinker 的数值 oracle，但不能证明
Qwen3.5-Omni Plus/Flash 具有相同宽度和专家数。

### 3.6 Talker、MTP、codec 与 ARIA

Talker 条件包含：

- Thinker 的多模态高层状态；
- 历史文本；
- 当前轮流式文本；
- Talker 专用 system prompt；
- 可选的音色文本描述和参考 codec sequence。

**ARIA，Adaptive Rate Interleave Alignment：**

- 将前代双轨文本/语音生成改成一个交错 token stream；
- 不依赖固定 interleave rate 或 MFA 强制对齐；
- 对任意生成前缀约束累计 speech:text token 比率不超过样本级全局比率；
- 支持任意文本前缀后继续生成语音；
- 目标是减少漏词、数字误读、发音不稳定和跨语言编码率差异。

Talker 自回归预测主 RVQ codebook，dense MTP 预测当前帧其余 codebooks，
causal Code2Wav 逐帧生成波形。

**未公开：**

- codebook 数量和大小；
- 精确 codec rate；
- Qwen3.5-Omni-Audio-Tokenizer 权重；
- codec encoder 和训练 loss；
- Talker、MTP、Code2Wav 的精确层数和维度。

前代 Qwen3-Omni 的 16 codebooks、5-layer MTP 等参数只能作为代理值，必须在
代码和报告中标明来源。

## 4. 训练流程

### 4.1 预训练

论文分三阶段：

1. **Encoder Alignment**
   - LLM 和 vision 从 Qwen3.5 初始化；
   - audio 从 AuT 初始化；
   - 冻结 LLM；
   - vision/audio 分开训练，先 adapter 后 encoder。
2. **General**
   - 解冻全部参数；
   - sequence length 为 32,768；
   - 约 4T tokens；
   - 论文分项相加为 4.29T，属于“约 4T”的口径。
3. **Long Context**
   - 扩展至 262,144；
   - 增加长音频和长视频比例。

### 4.2 Thinker 后训练

- Specialist Distillation：分别训练文本 Agent、代码、推理、视觉和音频教师，
  再蒸馏到统一模型；
- On-Policy Distillation：用同一问题的高质量文本条件回答，监督音频条件回答；
- Interaction-Aligned RL：优化多轮模态切换、persona drift 和长上下文指令保持。

### 4.3 Talker 后训练

- 超过 2,000 万小时多语语音及多模态上下文；
- 高质量、长上下文 continued pretraining，扩展到 64K；
- 多语偏好 DPO；
- 规则 reward、GSPO 和轻量 speaker fine-tuning。

### 4.4 不可精确复现项

- 基础预训练复合 loss；
- 各模态 loss 权重；
- AuT 的完整监督目标；
- 优化器、学习率、batch 和硬件；
- teacher checkpoint 和蒸馏温度；
- RL reward 公式；
- 训练数据身份、许可和清洗；
- codec 和 voice cloning 数据。

## 5. 流式推理事实与边界

论文基于内部 vLLM、`torch.compile` 和 CUDA Graph 报告理论延迟：

| 型号 | 单并发音频首包 | 单并发视频首包 | 单并发 RTF |
|---|---:|---:|---:|
| Flash | 235 ms | 426 ms | 0.178 |
| Plus | 435 ms | 651 ms | 0.187 |

codec decode 约 3–5 ms。论文没有披露 GPU 型号、数量、精度、batch、显存和完整
部署拓扑，因此这些数字不能作为本地实现的验收阈值。正确做法是在明确硬件和
输入条件下建立自己的 TTFT、TTFC、RTF 和并发基线。

## 6. 当前项目差异

### 6.1 当前 tokenizer 是前代 Qwen3 体系

本地 [Qwen3 tokenizer](../../src/tokenizer/Qwen3/tokenizer_config.json)使用
151,643 base vocabulary 和 152,064 模型 embedding vocabulary，与前代
Qwen3-Omni 同源，不是 Qwen3.5 约 250K tokenizer。

本分支已经解决“特殊 token ID 由 YAML 硬编码”的问题，但 tokenizer 本身仍不
能作为 Qwen3.5 profile 的 tokenizer。

### 6.2 媒体编码是单 token 占位

[SimpleVisionEncoder](../../src/qwen3_omni_pretrain/models/qwen3_omni_moe/modeling_thinker_vision_audio.py#L35)
将整图 resize、flatten 后映射为一个 token。

[SimpleAudioEncoder](../../src/qwen3_omni_pretrain/models/qwen3_omni_moe/modeling_thinker_vision_audio.py#L54)
将固定两秒、32,000 个 raw samples 映射为一个 token。

当前实现没有：

- Mel frontend 或 6.25 Hz AuT；
- patch sequence；
- 视频；
- 音视频交错；
- timestamp token；
- 160 ms temporal IDs；
- TM-RoPE。

### 6.3 当前 DeltaNet 不是官方 GDN

[GatedDeltaNetAttention](../../src/qwen3_omni_pretrain/models/qwen3_omni_moe/modeling_thinker_text.py#L330)
是简化实验实现。它与公开 Qwen3.5 GDN 的差异包括：

- 没有 K projection；
- 没有真正的 delta error correction；
- 没有 beta 和 z branch；
- recurrent state 是向量，不是 key×value matrix；
- 没有 conv/recurrent streaming cache；
- padding mask 没有参与 recurrent state 更新；
- 对 Q 使用当前 1D RoPE，语义与官方 GDN 不同。

当前 3:1 layer pattern 只在高层排列上相似，不能据此称为 Qwen3.5 实现。

### 6.4 Thinker、MoE 与 context 不匹配

当前项目：

- max positions 通常为 4096；
- MLP 是两矩阵 SiLU，而非官方骨干三矩阵 SwiGLU；
- expert 数和 top-k 是自定义小规模实验值；
- 仅有 legacy 全注意力短上下文 KV cache，没有 256K/GDN recurrent cache；
- 没有官方 GDN recurrent state；
- 没有 Qwen3.5 tokenizer。

[本地 30B 配置](../../configs/model/qwen3_omni_30b_moe.yaml)也不对应官方前代
30B-A3B，更不能作为 Qwen3.5-Omni Plus/Flash 的代理配置。

### 6.5 Talker、codec、训练和评测缺失

- Talker/Code2Wav 只有 config；
- [trainer_talker.py](../../src/qwen3_omni_pretrain/training/trainer_talker.py)
  为空；
- 没有 MTP、audio tokenizer、ARIA 或 voice enrollment；
- legacy all-MHA greedy 已缓存文本 K/V，媒体只在 prefill 编码一次；带
  DeltaNet/GDN 的 hybrid 路径仍没有 recurrent cache，只能显式回退全量计算；
- Stage-2 不是论文 Encoder Alignment；
- 没有蒸馏、OPD、RL、DPO 或 GSPO；
- evaluation 包未建立分模态和流式评测。

## 7. 差异矩阵

| 项目 | Qwen3.5-Omni / 开放参考 | 当前项目 | 结论 |
|---|---|---|---|
| 开放形态 | Omni 仅 API；骨干和前代开放 | 自定义源码 | 无官方 Omni 权重可对齐 |
| Tokenizer | 约 250K；公开骨干 248,320 | 152,064 embedding vocab | 需独立 profile |
| Context | 262,144 | 4,096 为主 | 缺长上下文 |
| Vision | SigLIP2 patch sequence | 默认整图单 token；实验层保留代理 sequence | 官方 encoder 仍缺 |
| Audio | Mel + 4×Conv2D + AuT，6.25 Hz | 默认 waveform 单 token；实验层保留代理 time sequence | 官方 AuT 仍缺 |
| Video | 动态 FPS、patch sequence | 实验契约可承载 video sequence，默认 runtime 无官方视频 encoder | 未端到端复现 |
| Fusion | AV interleave + timestamp | 默认固定媒体前缀；实验 assembler 可做时序组装 | 尚未接默认 Thinker |
| Position | TM-RoPE T/H/W + 160 ms | 默认 1D；另有实验 TM-RoPE builder | 未与 Qwen3.5 数值对齐 |
| Hybrid | 真正 GDN/full attention | 简化 DeltaNet/attention | 仅概念相似 |
| MoE | exact Omni 未公开；公开骨干 256/top-8 | 自定义小 MoE | 非代理配置 |
| Talker | Hybrid-MoE + ARIA | 仅配置 | 缺失 |
| MTP/codec | RVQ + dense MTP + Code2Wav | 仅配置 | 缺失 |
| Streaming | chunk prefill + 多状态 cache | legacy all-MHA typed KV；无 GDN/Talker/codec 状态 | 仅完成基础前置条件 |
| 训练 | alignment/general/long context | text Stage-1 + 简单 Stage-2 | 语义不同 |
| 后训练 | distillation/OPD/RL/DPO | 无 | 缺失 |

## 8. 推荐复现架构

### 8.1 Profile 隔离

建议建立四个逻辑 profile：

```text
legacy_prototype
qwen3_omni_reference
qwen35_omni_inspired
mimo_v25_experimental
```

`qwen35_omni_inspired` 使用独立 model type、tokenizer、config schema 和
checkpoint namespace。任何前代代理值都写入 metadata，例如：

```yaml
provenance:
  thinker_backbone: qwen3.5-open-reference
  omni_pipeline: qwen3-omni-open-reference
  codec: qwen3-omni-proxy
  exact_qwen35_omni_checkpoint_compatible: false
```

### 8.2 公共契约

- `MediaSequence`：embeddings、mask、grid、timestamp、modality。
- `SequenceAssembler`：placeholder replacement、AV interleave。
- `PositionBuilder`：TM-RoPE T/H/W 和连续 position。
- `DecoderState`：full-attention KV、GDN conv/matrix state、Talker state、
  codec state。
- `ProfileManifest`：来源、revision、支持能力和实验假设。

## 9. 分阶段实现方案

### B0：身份、版本与黑盒参考

1. 为本地自定义模型改用独立 model type。
2. 固定三类 reference：
   - Qwen3-Omni checkpoint 和 Transformers v5.2.0；
   - Qwen3.5-35B-A3B config/source revision；
   - Qwen3.5-Omni API snapshot。
3. API 黑盒数据只保存请求参数、响应 schema、延迟和公开输出，不保存秘密。
4. 所有配置字段标记来源等级。

退出条件：

- 本地和官方 config 不会互相误识别；
- 版本和 revision 可机器读取；
- 报告中不存在把公开骨干值写成 Omni Plus/Flash 精确值的表述。

### B1：Qwen3.5 骨干代理

以公开 `Qwen3_5Moe` 为数值参考，小模型保留结构比例：

- 248,320 tokenizer profile；
- 3:1 GDN/full attention；
- 真正 Q/K/V delta rule；
- beta、decay、z gate；
- depthwise conv + recurrent matrix state；
- Q/K norm 和 attention output gate；
- SwiGLU routed/shared experts；
- prefill 和 recurrent single-token decode。

退出条件：

- FP32 forward/backward 与 reference 数值对齐；
- padding 前后有效 token 输出一致；
- recurrent decode 与全序列 decode 一致；
- cache state shape 不随已处理序列长度增长。

### B2：Qwen3.5 论文级媒体序列

1. vision 使用公开 Qwen3.5 vision encoder 或明确的 SigLIP2 代理；
2. 实现 16 kHz/128 Mel/25-10 ms/四层 Conv2D/6.25 Hz AuT；
3. 实现动态 FPS；
4. 加入显式秒级 timestamp；
5. 实现 160 ms temporal IDs 和 T/H/W TM-RoPE；
6. 音视频按时间交错。

退出条件：

- 两秒音频产生约 12–13 帧，不再是一个 token；
- 同一时间事件的音频/视频 temporal ID 对齐；
- 多模态位置连续、无冲突；
- chunked 与 offline encoder 的有效区域一致。

### B3：Talker、MTP、codec 与 ARIA

第一版必须标记为使用前代 Qwen3-Omni codec 代理：

1. Talker 使用 Qwen3.5 Hybrid backbone 代理；
2. 主 codebook 自回归；
3. dense MTP 预测 residual codebooks；
4. Code2Wav 采用前代开放 renderer；
5. 实现 Talker system prompt；
6. 实现 ARIA 单流 scheduler 和 prefix-ratio invariant。

退出条件：

- 任意生成前缀满足 ARIA 比率约束；
- codebook CE/MTP mask 正确；
- codec 因果无 future leakage；
- chunked 与 whole decode 边界一致；
- 所有 codec 数值标明“前代代理”，不标成 Qwen3.5 官方值。

### B4：论文阶段式训练

1. S1：冻结 LLM，先 adapter 后 encoder。
2. S2：32K 多模态混合训练。
3. S3：按 32K、64K、128K、256K 渐进扩长。
4. Thinker 后训练：specialist distillation、OPD、interaction RL。
5. Talker：CPT、DPO/GSPO、speaker fine-tuning。

小规模复现目标是保留阶段和消融，不是复制论文数据量。

退出条件：

- freeze/unfreeze 自动断言；
- 每阶段 tiny dataset 可过拟合；
- 固定 seed resume 一致；
- 文本、图像、音频和 AV 分模态回归；
- 每次扩长都有短上下文质量和数值稳定性回归。

### B5：流式服务

前置状态：legacy all-MHA 已完成 typed KV、cached/uncached token parity、媒体单次
prefill、会话隔离以及暂停/恢复/cancel 原子性测试。Qwen3.5-native 工作仍包括：

1. Thinker chunked prefill；
2. 将已完成的 full-attention KV 契约接入 Qwen3.5 profile，并验证长上下文分页；
3. 实现 GDN conv/recurrent matrix state；
4. Talker/codec 独立状态；
5. audio ring buffer、背压和会话隔离；
6. 在正确性稳定后再接入 `torch.compile`、CUDA Graph 和服务框架。

退出条件：

- cached/uncached token 完全一致；
- 媒体 encoder 每个请求只运行一次；
- 记录 1/4/8 并发的 TTFT、TTFC、RTF 和显存；
- 打断和短 backchannel 不泄漏跨会话状态。

## 10. 依赖和验证策略

建议保留当前两个隔离环境，并新增一个固定 Qwen3.5 骨干环境，而不是原地升级：

- Qwen3-Omni oracle：Transformers 5.2.0；
- Qwen3.5 backbone oracle：固定 Transformers release/commit；
- 原型测试：现有 profile。

GDN 高性能路径可能需要 `flash-linear-attention` 和 `causal-conv1d`；无扩展时
可以使用数值等价的 PyTorch fallback，但必须记录性能回退。

核心测试：

- config/schema round-trip；
- tokenizer/embedding/LM head consistency；
- GDN forward/backward/padding/cache parity；
- media sequence length；
- TM-RoPE 时间对齐；
- ARIA property test；
- codec causality/chunk equivalence；
- freeze/unfreeze 和 deterministic resume；
- 分模态质量与流式性能。

## 11. 最终判断

Qwen3.5-Omni 的技术报告足以指导一个结构合理、可测试的论文级原型，但不足以
复现 Plus/Flash 的 checkpoint、训练结果和论文延迟。最可信的工程路径是：

1. 用前代 Qwen3-Omni 建立 Omni golden oracle；
2. 用公开 Qwen3.5 骨干建立 GDN/MoE 数值 oracle；
3. 对论文披露的 AuT、timestamp、ARIA 做独立实现；
4. 把所有未公开参数显式标成实验假设；
5. 用 API 做能力和 schema 黑盒对照，而不把 API 输出当作权重级验证。

满足这些边界后，可以称为 `Qwen3.5-Omni-inspired reproduction`；官方权重和
精确配置开放之前，不能称为 Qwen3.5-Omni Plus/Flash 的完整复现。
