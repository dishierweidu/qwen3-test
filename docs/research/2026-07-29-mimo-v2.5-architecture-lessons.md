# MiMo-V2.5 系列架构对比与项目改进建议

日期：2026-07-29
本地基线：`391d0186cb225f41f8e47aa600c36da0bc6b21e4`
目标：分析可借鉴机制，不把当前项目改名为 MiMo，也不宣称 MiMo checkpoint 兼容

实现状态更新（2026-07-30）：项目已完成 legacy 全注意力 typed KV cache、
prefill/decode 会话状态、媒体单次 prefill、暂停/恢复/cancel 原子性测试和 decode
benchmark，并已有独立的序列保真媒体契约。这完成了下文 C2 的 legacy 基线，
但尚未实现 MiMo 的 SWA/GA 双 cache pool、attention sink、MTP verification、
官方视觉/音频 encoder 或 EP/DeepEP。

## 1. 结论摘要

MiMo-V2.5 与 Qwen3.5-Omni 的开放边界不同。MiMo-V2.5 已开放 Base/Instruct
权重、配置、tokenizer 和参考推理代码，因此可以精确分析其网络结构；但完整
预训练、RL、MOPD 和生产推理系统没有全部开放。

MiMo-V2.5 最值得当前项目吸收的不是 310B/1.02T 参数规模，而是四个可独立验证
的工程原则：

1. 媒体必须保留可变长 patch/time sequence；
2. 先做 projector warmup，再逐步解冻；
3. MoE 必须真正稀疏、routed-only 且具备负载可观测性；
4. 正确 KV cache 是 SWA、MTP、长上下文和高效 serving 的共同前置条件；当前已
   完成 legacy full-attention 基线，下一步仍需实现 MiMo-specific SWA/GA cache。

当前项目虽然已有自定义 DeltaNet、MoE 和 TP 实验，但它们不是 MiMo 架构：

- MiMo 使用 Full Attention + Sliding Window Attention，不使用 SSM/DeltaNet；
- MiMo 第 0 层 dense，其余层 routed-only MoE；
- MiMo 使用可变长视觉/audio-tokenizer 序列；
- MiMo 主模型只输出文本，没有开放 Talker/Code2Wav；
- MiMo 的高效推理依赖 KV cache、MTP、EP/DeepEP 和专门 serving 后端。

因此建议建立独立 `mimo_v25_experimental` profile，在小规模模型上逐项做
SWA、稀疏 MoE 和 MTP 消融，不要静默改变现有 Qwen baseline。

## 3. 官方模型边界

官方 collection 包含四个 canonical checkpoint：

| 模型 | 模态和阶段 | 参数 | context | 固定 revision |
|---|---|---:|---:|---|
| `MiMo-V2.5` | 后训练，文本/图像/视频/音频到文本 | 310B / 15B active | 1M | `63651580ca774f8504f676040460aed3e1244ac1` |
| `MiMo-V2.5-Base` | 多模态 base | 310B / 15B active | 发布表 256K | `c9d050ce275c75318392dfbc11843516d41916c8` |
| `MiMo-V2.5-Pro` | 文本、Coding、Agent | 1.02T / 42B active | 1M | `21d1ecfecd7bd70f31be25ca49d7edd21f003659` |
| `MiMo-V2.5-Pro-Base` | 文本 base | 1.02T / 42B active | 发布表 256K | `1e94ccfda10a2e4dc62877139cd8b7d7b523a4be` |

官方公告和 Hugging Face metadata 将模型标为 MIT。模型仓库树没有单独的
`LICENSE` 文件，使用时应同时保存公告和 model-card metadata 作为许可证
证据。

发布表、固定 config 和 tokenizer metadata 并非所有字段都一致：例如
`MiMo-V2.5-Pro-Base` 的发布表写 256K，而当前固定 config 写 1M；主
`MiMo-V2.5` 的 tokenizer metadata 仍保留 131,072 的
`model_max_length`，但模型 config 和发布表写 1M。类似地，V2.5 的 GA/SWA
KV head 顺序在 model card 与 config/source 间也有冲突。报告中的“精确结构”
因此一律以表中固定 revision 的 config/source 为机器事实，发布表只保留为发布
口径；运行时不得依赖 tokenizer 的单一 `model_max_length` 字段推导已训练
context。

相关但不属于四个 canonical checkpoint 的官方 artifact：

- `MiMo-V2.5-Pro-FP4-DFlash`：专家 MXFP4 + DFlash draft；
- `MiMo-V2.5-DFlash`：当前 README 信息不足；
- `MiMo-V2.5-ASR`：独立 ASR 模型；
- `mimo-v2.5-tts`、voice design/clone：API 产品，没有开放对应权重；
- `MiMo-Code`：Agent/Coding harness，不是模型训练代码。

MiMo-V2.5 主 checkpoint 是统一多模态理解到文本模型。它不能用于填补本项目
缺失的 Talker 或 Code2Wav。

## 4. MiMo-V2.5 文本骨干

### 4.1 精确结构

| 项目 | MiMo-V2.5 | MiMo-V2.5-Pro |
|---|---:|---:|
| hidden size | 4096 | 6144 |
| decoder layers | 48 | 70 |
| dense / MoE | 1 / 47 | 1 / 69 |
| Full Attention / SWA | 9 / 39 | 10 / 60 |
| SWA window | 128 | 128 |
| Q heads | 64 | 128 |
| QK / V head dim | 192 / 128 | 192 / 128 |
| routed experts | 256 | 384 |
| experts per token | 8 | 8 |
| expert FFN | 2048 | 2048 |
| dense layer-0 FFN | 16384 | 16384 |
| MTP layers | 3 | 3 |

MiMo-V2.5 是 Hybrid SWA Transformer，不包含 SSM。大部分层只看 128-token
局部窗口，少数 Full Attention 层保留全局依赖。

### 4.2 Attention 细节

**公开配置/源码：**

- QK head dim 192，V head dim 128；
- 约 64 个 QK 维度使用 rotary；
- Global Attention `rope_theta=10,000,000`；
- SWA `swa_rope_theta=10,000`；
- SWA 带 attention sink；
- fused QKV；
- V2.5/Pro 的 value scale 分别约为 0.707/0.612；
- RMSNorm 使用标准乘法权重；
- embedding 和 LM head 不共享。

V2.5 model card 与当前 config 对 KV head 数的文字顺序存在冲突。当前固定
config/source 为 GA=4、SWA=8；model card 表格写成 GA=8、SWA=4。实现与实验
必须锁定 revision，并以实际 config/source 为机器可验证输入。

### 4.3 MoE

- 第 0 层使用 dense SwiGLU；
- 后续层使用 routed-only SwiGLU experts；
- 没有“每层 shared dense + routed MoE”的叠加路径；
- router 使用 sigmoid score、normalized top-8 和 `noaux_tc` correction bias；
- 没有 shared expert。

公开参考类在训练模式下拒绝 `noaux_tc`，说明它是 checkpoint 推理实现而不是
完整训练 router。当前项目不应直接复制该推理分支来替换已有可训练的 aux-loss
router；应先保留可训练 router，并把 MiMo router 作为独立研究任务。

### 4.4 MTP

Checkpoint 包含三层 MTP 权重，但通用 Hugging Face 类会忽略这些 key。实际
启用 MTP 需要 SGLang 等专门后端和正确的 speculative verification/rejection。
仅增加三个 next-token head 并直接接受 argmax，不构成正确 MTP 推理。

## 5. 视觉、视频、音频和 tokenizer

### 5.1 视觉/视频

MiMo ViT：

- 729M 参数；
- 28 层：24 window attention + 4 full attention；
- full 层位于 0、9、18、27；
- hidden 1280、FFN 4608；
- 32 Q heads、8 KV heads；
- QK/V head dim 均为 64；
- spatial patch 16、temporal patch 2、spatial merge 2；
- visual window 64；
- 最终投影到 LM hidden 4096；
- 同一个 ViT 处理图像和视频。

window pattern 同时使用行窗口和列窗口。编码后的可变长序列替换文本中的
image/video placeholder embedding，而不是固定前置一个全局 summary token。

### 5.2 音频

MiMo 音频理解包含两段：

1. Audio tokenizer
   - 24 kHz；
   - 128 Mel；
   - hop 240；
   - 20 个 RVQ codebooks；
   - 24 层 Audio Transformer；
   - 官方表概括为 12 SWA + 12 Full。
2. 主模型 audio adapter
   - 20 路 code embedding 分成 4 组；
   - 6 层本地 Transformer；
   - 2 层 projection 到 LM hidden 4096。

这条链路保留时间序列，但它是音频理解输入，不是开放的语音生成 Talker。

### 5.3 Tokenizer

固定 tokenizer 为 Qwen2Tokenizer BPE：

- base vocabulary 151,643；
- 32 个 added tokens；
- embedding vocabulary 152,576；
- EOS `<|im_end|>` 为 151645；
- PAD `<|endoftext|>` 为 151643；
- 默认 chat template 支持 thinking、tool XML 和 FIM token。

MiMo 和 Qwen 的媒体 token 位于相近 ID 区间，但字符串语义不同。当前项目已经
采用 tokenizer 驱动的 token ID 解析；这个机制必须扩展为 profile-specific
token schema，不能跨 tokenizer 复用裸数字。

## 6. 训练流程与开放边界

### 6.1 官方模型卡披露

MiMo-V2.5：

1. 文本预训练；
2. vision/audio projector warmup；
3. 大规模多模态预训练；
4. SFT + agentic post-training，并将 context 从 32K 扩展到 256K、1M；
5. RL + Multi-Teacher On-Policy Distillation。

模型卡声明：

- 总训练量约 48T tokens；
- 使用 FP8 mixed precision；
- context 最终支持 1M。

MiMo-V2.5-Pro 声明约 27T tokens，先做 32K 预训练，再扩展到 1M，并使用
SFT、领域教师和 MOPD。

### 6.2 未公开

- 数据来源、去重和模态混合比例；
- projector warmup、预训练、SFT、RL、MOPD 训练代码；
- teacher、reward、环境和完整 loss；
- `noaux_tc` 的训练实现；
- FP8 block-wise training recipe；
- 完整评测环境。

前代 MiMo-V2-Flash 报告可以解释继承机制，但不能被引用为 V2.5 的精确训练
配比。

## 7. 推理系统报告可借鉴内容

[2026-07 推理报告](https://arxiv.org/html/2607.13095v1)的重点是生产推理，
不是模型训练。报告披露：

- Full 与 SWA 使用独立 KV pool，使 SWA storage 严格为 `O(W)`；
- layerwise H2D prefetch；
- SWA-aware prefix/radix cache；
- GCache/RDMA 分层缓存；
- KV-cache-affinity routing；
- uncached-token priority；
- 按 0–64K、64–256K、256K–1M 分桶；
- multimodal encoder DP、batching 和 cache；
- MTP 在早期短 decode 上有更高收益。

报告只向 SGLang upstream 了部分改动，GCache、完整 production router 和调度器
不是完整开源组件。当前项目已完成单机 legacy full-attention cache 基线；应先
实现并验证 MiMo-specific SWA/GA cache，再考虑分布式缓存和生产调度。

## 8. 当前项目差异

### 8.1 配置身份与真实规模

当前配置文件名不能可靠代表真实参数：

- 本地 `7b_moe` 约 3.85B，而且 `num_experts=2`、`top_k=2`，所有专家都被
  激活，没有稀疏收益；
- 本地 `30b_moe` 的 YAML 写 `use_moe: false`，但又列出 11 个
  `moe_layer_indices`；
- 当前 source 允许 layer indices 覆盖全局布尔值，导致配置语义不直观；
- 本地模型的 total/active 参数与文件名差异较大。

应把真实 total/active 参数和每层 block type 作为配置加载后的强制输出与测试
snapshot。

### 8.2 Attention

当前项目的空 `deltanet_layer_indices` 会形成约 3:1 DeltaNet/attention
pattern。MiMo 则是 5:1 或 6:1 SWA/Full Attention。

两者差异：

- DeltaNet 是 recurrent linear attention 实验，SWA 是局部 softmax attention；
- 当前没有 attention sink；
- 当前没有 GA/SWA 独立 RoPE base；
- 当前已有 legacy full-attention KV cache，但没有 GA/SWA dual KV pool；
- 当前 QK/V 使用同一 head dim；
- 当前带自定义 query-dependent output gate；
- legacy cached decode 使用矩形 causal bias；训练/prefill 仍会 materialize
  `Q×K` mask，且尚无 MiMo-style window mask/kernel。

### 8.3 FFN 和 MoE

当前项目：

- MLP 是两矩阵 SiLU；
- 每层先运行 shared dense，再可选 routed MoE；
- router 使用 softmax + Switch-style aux loss；
- TP rank 保留并逐个运行所有专家；
- 没有 expert parallel/all-to-all。

MiMo：

- SwiGLU；
- 第 0 层 dense，其余 MoE 层 routed-only；
- sigmoid + correction bias；
- 256/384 experts，top-8；
- 高效 serving 依赖 EP/DeepEP。

当前 router 适合继续做小规模可训练实验，但不能称为 MiMo router。

### 8.4 多模态

[当前 vision/audio wrapper](../../src/qwen3_omni_pretrain/models/qwen3_omni_moe/modeling_thinker_vision_audio.py)
把图像和音频各压成一个 token。

MiMo 保留：

- image/video patch sequence；
- audio RVQ/time sequence；
- placeholder replacement；
- 可变长媒体和多段媒体。

当前项目因此无法评估 MiMo 式 visual window、audio sequence、encoder cache 或
长视频优化。

### 8.5 训练和推理

当前 Stage-2：

- 直接将全部 `model.parameters()`交给 optimizer；
- 没有 projector warmup；
- 当前明确拒绝 Stage-2 DDP；
- FP8 flag 不是 MiMo 的 block-wise FP8 recipe；
- legacy all-MHA greedy 已缓存文本 K/V，媒体 encoder 仅在 prefill 运行一次；
- hybrid DeltaNet 路径仍需显式 uncached fallback，且没有 SWA/GA dual pool、
  MTP verification 或通用 encoder cache。

legacy cache 前置条件已经补齐；仍需先完成阶段冻结和 MiMo-specific SWA cache，
再讨论 SWA/MTP 的真实性能收益。

## 9. 差异矩阵

| 子系统 | 当前项目 | MiMo-V2.5 | 改进含义 |
|---|---|---|---|
| 模型身份 | Qwen-style 自定义 config | `mimo_v2` | 建立独立 profile |
| Attention | DeltaNet + full SDPA | SWA + Global Attention | 不混用，独立消融 |
| Context | 4K 为主 | 1M | 先 cache，再渐进扩长 |
| RoPE | 单一 theta、partial 0.25 | GA/SWA 双 theta、partial rotary | profile-specific position |
| Cache | legacy full-attention typed KV；无 SWA/GA dual pool | Hybrid KV cache | baseline 已完成，MiMo-specific cache 待实现 |
| FFN | 两矩阵 SiLU | SwiGLU | 结构 profile |
| MoE | shared dense + 部分 routed | layer-0 dense + routed-only | 修正 active params 语义 |
| Router | softmax + aux | sigmoid + `noaux_tc` | 暂保可训练 router，独立研究 |
| Experts | 2/4/16 等，TP 内复制 | 256/384、top-8、EP | 先 8/top-2 + EP |
| Vision | 单 token | 28L ViT sequence | 先做小型 sequence encoder |
| Audio | raw waveform 单 token | RVQ/time sequence | 保留时间结构 |
| Video | 无 | temporal patch | 共享 sequence contract |
| Fusion | 固定前缀 | placeholder replacement | 重构 assembler |
| Training | 全参 Stage-2 | projector warmup → multimodal | 增加阶段冻结 |
| MTP | 无 | 3 层 | cache 正确后实现 |
| 输出 | 文本；Talker 占位 | 文本 | MiMo 不解决语音输出 |

## 10. 可安全吸收的改进方案

### C0：配置契约与可观测性

1. 增加显式 architecture profile。
2. 禁止 layer indices 静默覆盖全局布尔值。
3. 校验 `top_k < num_experts`；否则标成 dense ensemble。
4. 每次构建输出：
   - 每层 block type；
   - total/active params；
   - routed/shared params；
   - attention/cache 类型。
5. tokenizer token schema 与 profile 绑定。

最小实验：

- meta-device 构建全部现有配置；
- snapshot 每层结构和参数；
- 当前 7B `top-2/2` 和 30B 布尔/索引冲突必须 fail-fast。

### C1：媒体序列保真与 projector warmup

第一版不复制 729M/261M 规模，而是实现小型可变长 encoder：

- image patch sequence；
- audio window/code sequence；
- placeholder replacement；
- Thinker freeze + projector warmup；
- 随后逐步解冻。

最小实验：

- 1-token、16/64 image tokens、16/64 audio tokens 对照；
- 图像象限顺序和音频音调先后合成任务；
- media shuffle/ablation；
- 多模态验证 CE；
- 文本验证 CE 相对退化不超过预先设定阈值。

### C2：正确生成 cache

legacy full-attention 基线已经完成：

- typed full-attention K/V state，缓存 RoPE 后、未重复的本地 KV heads；
- 媒体只在 prefill 编码一次；
- cached/uncached token parity 与统一 generation engine；
- cache bytes、峰值内存、延迟和运行 manifest benchmark；
- 标准实现与两 rank Gloo TP 的本地 shard/owner 隔离测试。

进入 C3 前仍需把这一契约扩展为 GA/SWA 双 cache pool，并定义 window eviction、
attention sink 和长上下文分页语义。

最小实验：

- FP32 cached/uncached logits 最大误差 `<1e-5`；
- greedy token 完全一致；
- prompt 128/512/2K/4K、output 32/128 的延迟/吞吐/内存；
- 媒体 encoder 调用次数为 1。

### C3：MiMo-style SWA/GA

建立 6 或 12 层小模型 profile：

- window 128；
- 约 5:1 SWA/GA；
- SWA attention sink；
- GA/SWA 独立 RoPE；
- 第一轮不混 DeltaNet。

最小实验：

- `T≤128` 时，同权重 SWA 与 full attention 输出一致；
- window 外 token 不直接影响单个 SWA 层当前输出；
- cached/uncached parity；
- 1K/4K passkey/needle；
- SWA KV bytes 随总长度保持 `O(W)`；
- 与 full attention、DeltaNet 分开报告质量、内存和吞吐。

### C4：真正稀疏的 routed-only MoE

从 8 experts/top-2 开始：

- 第 0 层 dense；
- 后续指定层 routed-only；
- SwiGLU experts；
- 保留 softmax + aux-loss 可训练 router；
- 记录 router entropy 和 load。

最小实验：

- active/total 显著小于 1；
- 每 expert token 数和 max/mean load；
- 与 FLOPs/参数匹配的 dense baseline 对照；
- max/mean 长期过高时先解决 load balance；
- 扩大专家数前实现 expert parallel/all-to-all。

### C5：渐进长上下文

在 cache 和 SWA 正确后，按 4K、16K、32K 扩展。每次记录：

- 分桶 perplexity；
- passkey/needle；
- 数值稳定性；
- cache memory；
- 短上下文回归。

不能仅修改 `max_position_embeddings` 就宣称支持 1M。

### C6：MTP

先实现一个 next-token predictor，再扩展三层：

- teacher-forced next-2/next-3 loss；
- speculative verification/rejection；
- rejection 后状态修复；
- 采样分布一致性。

最小实验：

- speculative 输出与原模型采样分布一致；
- 记录 acceptance length；
- 自然文本和随机 token 分开测；
- 只有端到端 speedup 大于 1 才继续增加复杂度。

### C7：多模态 serving

真实 sequence encoder 稳定后，再实现：

- media hash；
- encoder batching；
- embedding cache；
- encoder/prefill/decode 分离；
- cache key 包含所有预处理参数。

最小实验：

- 相同和不同媒体请求的命中率；
- P50/P90 latency；
- encoder QPS；
- 错误 cache key 不得跨预处理配置复用。

## 11. 暂缓项

当前不建议直接投入：

- 256/384 experts；
- 1M context；
- `noaux_tc` 训练；
- FP4 QAT、DFlash；
- GCache/RDMA；
- Agent RL/MOPD；
- 生产级分布式调度。

这些任务依赖已经正确的 sequence encoder、cache、SWA、EP、稳定 SFT 和评测。
跳过前置条件会得到无法归因、无法验证的“大模型外形”。

Talker/Code2Wav 也不应从 MiMo 主模型推导，应继续使用 Qwen3-Omni 开放链路作为
主参考。

## 12. 最终判断

MiMo-V2.5 为当前项目提供了很有价值的长上下文和高效推理设计，但最优吸收方式
不是复制 310B 配置，而是依次验证：

1. 配置契约和真实参数统计；
2. 可变长媒体序列与 projector warmup；
3. 保持已完成的 legacy KV cache 正确性门禁；
4. 实现 MiMo-specific SWA/GA cache 并做独立消融；
5. routed-only 稀疏 MoE；
6. 正确 speculative MTP；
7. 最后再做 serving cache 和分布式优化。

这些机制应保留 `MiMo-style experiment` 标签，与官方 Qwen3-Omni reference
和 Qwen3.5-inspired profile 分离。只有在 config、state dict 和数值均完成官方
对齐时，才可以讨论 MiMo checkpoint compatibility。
